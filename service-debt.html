Platform services / debt

agentmesh · platform service · debt

Debt

The ledger keeps one record, with one numbering, for two kinds of debt. Dependency debt is owed to the owner of something that depends on a change. It has a deadline, and until it is closed it holds back the acts it names (update, promote, rollback or decommission) on the changed agent or solution. Technical debt is what the AgentMesh team owes itself, and it holds nothing back. The four requests here are the ones the ledger defines (services/src/ledger/requests.ts).

Who can call it: The owner of an agent or a solution reads the items against it. The platform files items and moves them, with the ledger's key (the debt scope); operators with the read or reports scope read every item.

What a call costs: No model is called. A call is a read or a write of the ledger's database.

The requests

Each request has one name, written the same way on every door. The request debt.file is the MCP tool debt_file, the command agentmesh debt file, the TypeScript method mesh.debt.file() and the Rust method mesh.debt().file().

A door is a way of reaching the platform. The SDKs are libraries your program calls, in TypeScript and in Rust. The command line is the agentmesh command. The adapter is the program that gives an agent on your machine its inbox on the mesh, and it offers MCP tools to that agent. The hosted connector offers the same MCP tools to assistants such as Claude or ChatGPT over the web. Where a door behaves differently, the request says so.

debt.file

File a debt item

File one item; the ledger gives it the next number.

Here is the same request on each door.

TypeScript SDK

const answer = await mesh.debt.file({
  kind: "kind-1",
  against: "against-1",
  what: "what-1",
  who: "who-1"
});

Rust SDK

let answer = mesh
    .debt()
    .file(DebtFileInput {
        kind: "kind-1".into(),
        against: "against-1".into(),
        what: "what-1".into(),
        who: "who-1".into(),
        ..Default::default()
    })
    .await?;

MCP tool

debt_file
{
  "kind": "kind-1",
  "against": "against-1",
  "what": "what-1",
  "who": "who-1"
}

Command line

agentmesh debt file kind-1 against-1 what-1 --who who-1

debt.list

List debt items

Items by kind, state, asset, whom they are owed to, or the act they hold back, newest number first. An owner names their own agents or solutions in against and sees the items against them; an operator may list everything.

Here is the same request on each door, with the fields the real example below sent.

TypeScript SDK

const answer = await mesh.debt.list({ against: ["example-one.test-rig+claude@agentmesh.ai"] });

Rust SDK

let answer = mesh
    .debt()
    .list(DebtListInput {
        against: Some(vec!["example-one.test-rig+claude@agentmesh.ai".into()]),
        ..Default::default()
    })
    .await?;

MCP tool

debt_list
{
  "against": [
    "example-one.test-rig+claude@agentmesh.ai"
  ]
}

Command line

agentmesh debt list --against example-one.test-rig+claude@agentmesh.ai

debt.transition

Move a debt item

Move one item to a new state, saying who and with what evidence. An item that is resolved, overridden or dropped can only be opened again. Resolving, dropping, overriding and opening again each need evidence. Only dependency debt can be overridden, and only once its deadline has passed.

Here is the same request on each door.

TypeScript SDK

const answer = await mesh.debt.transition({ number: 1, to: "to-1", who: "who-1" });

Rust SDK

let answer = mesh
    .debt()
    .transition(DebtTransitionInput {
        number: 1,
        to: "to-1".into(),
        who: "who-1".into(),
        ..Default::default()
    })
    .await?;

debt_transition

What uses it

What uses itWhat for
The Debt ledger pageMesh admins read every debt item by kind, state and asset there, and open one to see its words and each change of its state.
The What is owed cardAn owner sees the debt filed against their agent on the agent's page, and against their solution on the solution's Overview, read from the same ledger.
Renaming AgentMesh's own agentsWhen the operator renames or moves an agent on the page that lists AgentMesh's own agents, the platform files a debt item for each user still reaching it by its old name.
The technical debt file scriptThe script loads docs/technical-debt.md into the ledger once per environment and writes the file back out from the ledger, and a check refuses hand edits to that file.
The deployment manager (planned)The plan is for it to check the ledger before it promotes, rolls back or retires an agent, and to refuse when an open item blocks that step.
