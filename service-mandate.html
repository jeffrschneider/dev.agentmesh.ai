Platform services / mandate

agentmesh · platform service · mandate

Mandates

Read an organization's charter and the mandates issued under it (Agent Mandate, https://agentmandate.net), and check whether a person may commit an organization to an act. A charter names an organization's domain and the keys that hold root authority; a mandate is signed, bounded authority given to one person: which acts, up to what ceiling, on which offerings, until when. Every chain verifies from the documents alone, so each read returns the documents themselves.

Where it works: it needs the AgentMesh platform. On a mesh without it, every door answers with NOT_AVAILABLE: "mandate.organizations is not available on this mesh: https://mesh.example.com does not offer it. It needs the AgentMesh platform."

Who can call it: Anyone, with or without an agent. Charters and mandates are public by design, so a counterparty can check who may commit an organization before it relies on them.

What a call costs: No model is called. A call is one read of the charter and mandate registry.

The requests

Each request has one name, written the same way on every door. The request mandate.organizations is the MCP tool mandate_organizations, the command agentmesh mandate organizations, the TypeScript method mesh.mandate.organizations() and the Rust method mesh.mandate().organizations().

A door is a way of reaching the platform. The SDKs are libraries your program calls, in TypeScript and in Rust. The command line is the agentmesh command. The adapter is the program that gives an agent on your machine its inbox on the mesh, and it offers MCP tools to that agent. The hosted connector offers the same MCP tools to assistants such as Claude or ChatGPT over the web. Where a door behaves differently, the request says so.

mandate.organizations

List organizations

List the organizations whose charters this registry hosts, a page at a time in id order, each with its domain, name, state and version.

Here is the same request on each door, with the fields the real example below sent.

TypeScript SDK

const answer = await mesh.mandate.organizations({ limit: 3 });

Rust SDK

let answer = mesh
    .mandate()
    .organizations(MandateOrganizationsInput {
        limit: Some(3),
        ..Default::default()
    })
    .await?;

MCP tool

mandate_organizations
{
  "limit": 3
}

Command line

agentmesh mandate organizations --limit 3

What you send

FieldTypeRequiredWhat it means
cursortextNoWhere to continue from: the next value of an earlier answer.
limitwhole numberNoAt most this many, 1 to 200. If you leave it out: 50.

What comes back

FieldTypeAlways thereWhat it means
organizationslist of objectsYesThe organizations, in id order.
organizations[].organizationtextYesThe organization's id, org_ followed by 16 characters.
organizations[].domaintextYesThe domain its charter is bound to, which is the verified part.
organizations[].nametextYesThe name its charter gives.
organizations[].stateone of: active, suspendedYesSuspended while its domain proof cannot be found.
organizations[].versionwhole numberYesThe charter's current version.
nexttextNoWhere the next page starts. Absent on the last page.

Refusals

CodeWhat it means
INPUT_INVALIDA field is wrong. The words say which.
UNAVAILABLEThis mesh runs no charter and mandate registry, or it did not answer. Try again in a minute.

mandate.check

Check authority

Check whether a person's account may commit an organization to an act now, or could when it signed: the check at approval (Agent Mandate section 7) and, for an act on an Agent NDA, its check (section 7.2). A refusal names the check that failed.

Here is the same request on each door.

TypeScript SDK

const answer = await mesh.mandate.check({
  organization: "org_7k2m9q4w1x8e5r3t",
  account: "acct_2c9f7e1a",
  power: "nda",
  nda_categories: ["solicitation", "agreement_terms"]
});

Rust SDK

let answer = mesh
    .mandate()
    .check(MandateCheckInput {
        organization: "org_7k2m9q4w1x8e5r3t".into(),
        account: "acct_2c9f7e1a".into(),
        power: "nda".into(),
        nda_categories: Some(vec!["solicitation".into(), "agreement_terms".into()]),
        ..Default::default()
    })
    .await?;

MCP tool

mandate_check
{
  "organization": "org_7k2m9q4w1x8e5r3t",
  "account": "acct_2c9f7e1a",
  "power": "nda",
  "nda_categories": [
    "solicitation",
    "agreement_terms"
  ]
}

Command line

agentmesh mandate check --organization org_7k2m9q4w1x8e5r3t --account acct_2c9f7e1a --power nda --nda-categories solicitation,agreement_terms

What you send

FieldTypeRequiredWhat it means
organizationtextYesThe organization's id.
accounttextYesThe account of the person who would act.
powerone of: form, amend, terminate, award, nda, writeYesThe act: form, amend or terminate a statement of work, award a request for work, any act on an Agent NDA, or a change made through a resource the organization shares.
mandatetextNoThe mandate the act cites. Only that mandate is then checked.
signer_keytextNoThe public key the act was signed with. Check 1 fails when it is not the mandate's holder key.
committedwhole numberNoThe price the act commits, in the ceiling's unit, for check 4. Leave it out for an act that commits nothing.
currencytextNoThe currency of committed.
month_to_datewhole numberNoWhat the account has already committed for the organization this calendar month, before this act. Required with committed.
offeringslist of textNoThe offerings the act covers, for check 5.
resourcetextNoFor a write or amend made through a resource proxy: the resource the act targets, for check 5 against the mandate's scope.resources.
nda_categorieslist of textNoFor an act on an Agent NDA: the categories the agreement covers.
atdate and timeNoWhen the act was signed. Absent means now.

What comes back

FieldTypeAlways thereWhat it means
okyes or noYesWhether the account may commit the organization to the act.
mandatetextNoThe mandate that gives the authority, when it may.
chainlist of textNoThat mandate and the mandates above it, up to root authority.
settlement_payerone of: holder, organizationNoWhose balance pays for what is approved under it.
failedone of: holder, in_force, power, ceiling, scope, nda_categoriesNoThe check that failed, when it may not.

Refusals

CodeWhat it means
INPUT_INVALIDA field is wrong, such as committed without month_to_date. The words say which.
UNAVAILABLEThis mesh runs no charter and mandate registry, or it did not answer. Try again in a minute.

A real example

This request, mandate.organizations, was sent on 2026-10-22 to the AgentMesh development system, by the hosted connector's agent through the MCP tools. The development system hosts no charters, so the list is empty.

It sent this through the hosted connector:

mandate_organizations {"limit":3}

The platform answered:

{
  "organizations": []
}

What uses it

What uses itWhat for
The organization's Signing authority section in the appIt lists the organization's charter and the mandates its people hold, and files new ones, through the same registry.
Approving a statement of workWhen a party names an organization, approving a formation, an amendment or a termination runs the same check before anything is signed.
Agent NDA signing (planned)The plan is for a signature made for an organization to be checked against the mandate it names, with the nda power and its categories.
