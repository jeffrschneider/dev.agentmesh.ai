Platform services / schedules

agentmesh · platform service · schedules

Schedules

A schedule runs a solution, or sends an agent a job, on a repeating time: every day, every working day, every week or every month, at a time in a time zone. A solution's schedule may also have no time and run only when asked. Each run goes as the person who made the schedule, on their account.

Where it works: it needs the AgentMesh platform. On a mesh without it, every door answers with NOT_AVAILABLE: "schedules.create is not available on this mesh: https://mesh.example.com does not offer it. It needs the AgentMesh platform."

Who can call it: People in the solution's organization: its owner and admins see every schedule there; anyone else sees the ones they made and the ones whose solution or agent they can reach. A schedule somebody cannot see answers as if it did not exist.

What a call costs: Making, listing and pausing call no model and are plain reads and writes. Each run a schedule starts costs what that solution or job costs, on the maker's account; a schedule cannot run something that charges.

The requests

Each request has one name, written the same way on every door. The request schedules.create is the MCP tool schedules_create, the command agentmesh schedules create, the TypeScript method mesh.schedules.create() and the Rust method mesh.schedules().create().

A door is a way of reaching the platform. The SDKs are libraries your program calls, in TypeScript and in Rust. The command line is the agentmesh command. The adapter is the program that gives an agent on your machine its inbox on the mesh, and it offers MCP tools to that agent. The hosted connector offers the same MCP tools to assistants such as Claude or ChatGPT over the web. Where a door behaves differently, the request says so.

schedules.create

Make a schedule

Make a schedule that runs one of your solutions, or sends one of your agents a job, on a repeating time.

Here is the same request on each door.

TypeScript SDK

const answer = await mesh.schedules.create({ name: "name-1" });

Rust SDK

let answer = mesh
    .schedules()
    .create(SchedulesCreateInput {
        name: "name-1".into(),
        ..Default::default()
    })
    .await?;

MCP tool

schedules_create
{
  "name": "name-1"
}

Command line

agentmesh schedules create name-1

What you send

FieldTypeRequiredWhat it means
nametextYesWhat to call it.
solutiontextNoThe id of the solution it runs. Give this or to_agent.
to_agenttextNoThe handle or key of the agent it sends a job to. Give this or solution.
offeringtextNoFor an agent: which of its offerings (the jobs it offers, by name) to send.
messagetextNoFor an agent: what to ask it each time.
answersobjectNoFor a solution: its Start form's answers, by field.
repeatone of: day, weekday, week, monthNoHow often: every day, every working day, every week or every month. If you leave it out: "day".
daytextNoFor week, the day of the week, such as Monday; for month, the day of the month, 1 to 28.
timetextNoThe time of day, as HH:MM in 24 hours. If you leave it out: "09:00".
zonetextNoThe time zone, such as America/Denver. If you leave it out: "UTC".
timedyes or noNoFor a solution: false makes it run only when asked (run_now). If you leave it out: true.
approvalsone of: through, askNoWhether the run's approval steps run straight through or stop and ask. If you leave it out: "ask".
tellone of: each, failures, neverNoWhen to email the maker: after each run, only after a failure, or never. If you leave it out: "failures".
orgtextNoThe organization to make it in. Your own when left out.

Rust SDK

    .schedules()

    })
    .await?;

MCP tool

schedules_run_now
{
  "id": "id-1"
}

Command line

agentmesh schedules run_now id-1

What you send

FieldTypeRequiredWhat it means
idtextYesThe schedule's id.

What comes back

FieldTypeAlways thereWhat it means
runtextNoThe run's id.
addresstextNoThe run's page, from the moment it starts. Give it to the person; runs_show says where it stands.
solutiontextNoThe solution it ran.
outcometextYesWhere the run stands: running, done, or another state.
wordstextNoWhat the run said, when it said something.

Refusals

CodeWhat it means
INPUT_INVALIDA field is wrong. The words say which.
NOT_FOUNDNo schedule of a solution that you can see by that id. An agent job cannot be run now; it runs at its times.
NOT_STARTEDThe run could not be started. The words say why.
OFFSchedules are switched off on this system.
NO_ACCOUNTThis agent belongs to no account, so it cannot run a schedule.

What uses it

What uses itWhat for
The Schedules page in the appIt lists an organization's schedules, makes and edits them, pauses and resumes them, and starts one at once with Run now, through the same schedule code the service uses.
The Variations tab of solutionsIt lists one solution's variations and starts a run of one when the person presses Run now.
Competitor watchesApproving a competitor watch creates the schedule that sends its brief daily or weekly.
The Build page in the appWhen a plan built from a prompt says it should repeat, the build puts the new solution on a schedule.
The watcher agent (planned)The Agent SDLC plan says the watcher, which watches agents and their cost, will be a platform agent that a platform schedule runs every hour.
