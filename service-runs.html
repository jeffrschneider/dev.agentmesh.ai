Platform services / runs

agentmesh · platform service · runs

Runs

The record of every piece of work that ran for an account: a solution run, a job sent to an agent, a Try, a build or a deploy. Each says who asked, on whose behalf, by which door, and what it cost. A run of one of the account's own solutions can be started here too, now, with its answers.

Where it works: it needs the AgentMesh platform. On a mesh without it, every door answers with NOT_AVAILABLE: "runs.list is not available on this mesh: https://mesh.example.com does not offer it. It needs the AgentMesh platform."

Who can call it: The account the runs belong to: the account each one ran for and paid for, whoever asked for it. Nobody else's runs come back. A run is started only of a solution in an organization the account is in, as that account and on its account, the way Run in the app starts one.

What a call costs: Listing runs or solutions and showing a run call no model: each is one read of the run accounting records, which are kept for 90 days, or of the solutions. A run that runs.start begins costs what the solution's steps cost, on your account. A solution that charges for its runs is started only by the person signed in, in the app or through the hosted connector.

The requests

Each request has one name, written the same way on every door. The request runs.list is the MCP tool runs_list, the command agentmesh runs list, the TypeScript method mesh.runs.list() and the Rust method mesh.runs().list().

A door is a way of reaching the platform. The SDKs are libraries your program calls, in TypeScript and in Rust. The command line is the agentmesh command. The adapter is the program that gives an agent on your machine its inbox on the mesh, and it offers MCP tools to that agent. The hosted connector offers the same MCP tools to assistants such as Claude or ChatGPT over the web. Where a door behaves differently, the request says so.

runs.list

List your runs

Your account's runs, newest first: who asked, by which door, what kind of work, which agent, and what it cost.

Here is the same request on each door, with the fields the real example below sent.

TypeScript SDK

const answer = await mesh.runs.list({ limit: 1 });

Rust SDK

let answer = mesh
    .runs()
    .list(RunsListInput {
        limit: Some(1),
        ..Default::default()
    })
    .await?;

MCP tool

runs_list
{
  "limit": 1
}

Command line

agentmesh runs list --limit 1

What you send

FieldTypeRequiredWhat it means
dayswhole numberNoHow many days back, 1 to 90. If you leave it out: 7.
to_agenttextNoOnly the runs that went to this agent, by its key.
limitwhole numberNoAt most this many, 1 to 500. If you leave it out: 100.

What comes back

FieldTypeAlways thereWhat it means
runslist of objectsYesThe runs, newest first.
runs[].idtextYesThe run's accounting record.
runs[].atdate and timeYesWhen it started.
runs[].worktextYesWhat kind of work: run, job, try, send, plan, build, deploy, wake or skip.
runs[].origintextYesThe door it came in by: app, email-order, schedule, x-mention, prompt-to-prod, try, mcp, api, deploy, mesh or trial.
runs[].requested_byobjectYesWho asked.
runs[].requested_by.kindtextYesaccount, friend, schedule, x, platform, test, agent or visitor.
runs[].requested_by.labeltextYesWho, in the words your Monitor uses.
runs[].agenttextNoThe agent it went to, by key.
runs[].reftextNoWhat it started, when it has an id: a run, a plan, a conversation.
runs[].jobswhole numberYesHow many jobs agents reported doing for it.
runs[].cost_usdnumberYesWhat those jobs reported spending on models, in US dollars.
window_dayswhole numberYesHow many days back it read.
totalwhole numberYesHow many runs there were in the window, before the limit.

NO_ACCOUNTThis agent belongs to no account, so it has no runs.

runs.start

Start a run of a solution

Start one run of one of your solutions now, as you and on your account, with its Start form's answers, the way Run in the app starts one. runs_solutions says what each solution asks for. Its approval steps stop and wait for a person in the app. It answers with the run's id and its page as soon as the run starts; runs_show says where it stands after that.

Here is the same request on each door.

TypeScript SDK

const answer = await mesh.runs.start({
  solution: "sol_0b8c2f",
  answers: { topic: "How tides work" }
});

Rust SDK

let answer = mesh
    .runs()
    .start(RunsStartInput {
        solution: "sol_0b8c2f".into(),
        answers: Some(serde_json::json!({"topic":"How tides work"}).as_object().cloned().unwrap_or_default()),
    })
    .await?;

MCP tool

runs_start
{
  "solution": "sol_0b8c2f",
  "answers": {
    "topic": "How tides work"
  }
}

Command line

agentmesh runs start sol_0b8c2f --answers "{\"topic\":\"How tides work\"}"

What you send

FieldTypeRequiredWhat it means
solutiontextYesThe solution's id, from runs_solutions.
answersobjectNoIts Start form's answers, by each input's key: words or a web address as text; a file as { "name", "media_type", "data_b64" } with its bytes in base64, or a list of them for an input that takes many; a document asked for in parts as { "as": "fields", "parts": { <name>: text } }. These are the answers schedules_create takes and Run in the app sends. The whole request is at most 1 MB, so a larger file is added in the app.

What comes back

FieldTypeAlways thereWhat it means
runtextYesThe run's id.
addresstextYesThe run's page, from the moment it starts. Give it to the person; runs_show says where it stands.
solutiontextYesThe solution it is a run of.
statetextYesWhere it stands now: running, waiting, done, failed or stopped.

Refusals

CodeWhat it means
INPUT_INVALIDA field is wrong, or an answer is one its input does not take, such as a file of the wrong kind or one too large. The words say which.
NOT_FOUNDNo solution you can run by that id. A solution in an organization you are not in answers the same as one that does not exist.
MISSING_INPUTSAn input the run needs was left out. The words name each one; runs_solutions says what each takes.
CHARGESIt charges for each run, so only the person signed in starts one, in the app or through the hosted connector.
NOT_STARTEDThe run could not be started: a run of it is already going and it runs one at a time, an agent on it is out of service, or an agent on it has an update waiting for approval. The words say which.
PAUSEDEverything this account owns is paused with the Kill Switch, so nothing new starts. Resume on the Kill Switch page first.
NO_ACCOUNTThis agent belongs to no account, so it cannot start a run.

What uses it

What uses itWhat for
The Monitor page in the appIts Requested by card reads the same run records for the account and names who asked for each piece of work in the same words, such as you, a friend or a schedule.
The Run page in the appThe page for one run shows it read only, with the same owner check, the same read, the same address and the same link to share that this service gives.
The X botWhen a post on X starts a run, the bot replies with the run's view-only link and later reads where the run stands through the same run view.
The Replay a run pageIt reads the same job and cost records for a run to show what each agent spent in the replay.
Assistants sending messagesWhen a message an assistant sends through the hosted connector starts a run, the answer carries the run's address in the same form this service gives.

Versions and old names

VersionDateWhat changed

22026-10-05runs.show and runs.step were added, so an assistant can say where a run stands and what a step delivered.
32026-10-16runs.start starts a run of one of your solutions now, with its answers, and answers with the run's id and address. runs.solutions lists the solutions you can run, with the inputs each one asks for.
